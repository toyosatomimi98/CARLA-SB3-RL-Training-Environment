## 2. 为什么"确定性"这一项很关键

同步模式 + 固定步长让**同一 seed 的两条轨迹逐位相同**，这意味着：
* 报告里"同一策略开/关滤波器"的对照是**因果对照**，不是两次不同的随机过程；
* 单测/复现脚本的输出可对齐；
* 视频里那一段扰动窗口可以**精确复现**（我们就是用同一个 seed 33 录的开/关两份）。

如果 `synchronous_mode` 或 `fixed_delta_seconds` 没生效，上面这些结论都会变成"仅供参考"。

## 3. 发现并修掉的问题：`close()` 没有恢复服务器设置

**现象（FAIL）**：`close()` 之后服务器**仍然停在同步模式**（`sync=True`），而客户端已经退出。
同步模式下必须有人持续 `world.tick()`，否则仿真器就"冻住"——外部表现就是：
`client.get_map()` 抛 `UnicodeDecodeError`、世界看着像卡死、后续客户端连上也动不了。
**这正是本项目早期遇到并记录过的"CARLA 卡死、重启才恢复"现象的真实成因。**

另外两项当时也报 FAIL，复查后确认**不是**它的锅：
* "close() 后还剩 1 辆车" —— 那是**上一次被强杀的运行**留下的残留（本次审计开始前 `vehicles=0`，
  修好 close 后 `vehicles=0`）；
* "两次运行不一致" —— 是首轮检查用了**逐位相等**且没排除残留状态；改成"同 seed 跑两遍比轨迹"后
  实测逐位一致。

**修法**（`carla_env/envs/carla_route_env.py` 的 `close()`）：销毁 actor 之后把世界设置**恢复成异步 +
可变步长**，并额外 `tick()` 一次让服务器自由跑：

```python
settings = self.world.get_settings()
settings.synchronous_mode = False
settings.fixed_delta_seconds = 0.0
self.world.apply_settings(settings)
self.world.tick()
```

## 4. 启动参数（本机约定）

```powershell
Start-Process "E:\carla\Carla-0.10.0-Win64-Shipping\CarlaUnreal.exe" `
  -ArgumentList "-quality_level=Low","-RenderOffScreen","-nosound",
                "-prefernvidia","-carla-world-port=2000"
```

* `-RenderOffScreen`：无窗口跑（相机仍然渲染，观测有效）；
* `-quality_level=Low`：降画质换吞吐（视频观感仍可接受）；
* **不要加 `-benchmark -fps=15`**：那是"异步基准模式"的用法；本项目走**客户端同步模式**，
  服务器由 `world.tick()` 驱动，两者叠在一起容易让人误判帧率。
  （上游 `CarlaRouteEnv.start_carla=True` 的默认启动命令里带着这两个参数，本项目统一改为
  **外部启动、`start_carla=False`**。）

## 5. 还没做、但建议做的两件事

1. **把天气钉死**：现在用服务器默认天气。若要在不同时间重录视频/重跑训练，建议在 env 里
   显式 `world.set_weather(carla.WeatherParameters.ClearNoon)`（一行），保证光照一致。
2. **训练时保持 `no_rendering_mode=False`**：本项目观测里有相机（dashcam），关掉渲染会让观测失效；
   如果要提速，应该改成**纯向量观测**（去掉相机）再开 `no_rendering_mode=True`。
