# 01 · 环境审计与移植记录（CARLA 0.10.0 + SB3）

> 本文记录"老师发的 safety homework（设计 CBF + 演示 safety filter）"在本机落地时，
> **本机环境到底有什么、缺什么、仓库要怎么改**。所有改动只发生在这个 fork 的本地工作区，
> 没有 push、也没有碰上游仓库。

## 1. 本机环境审计（事实）

| 项目 | 结论 | 证据 |
| --- | --- | --- |
| CARLA 运行时 | **有**：`E:\carla\Carla-0.10.0-Win64-Shipping\CarlaUnreal.exe`（UE5.5） | `E:\carla\CARLA部署说明.txt` |
| CARLA Python 包 | **有**：`E:\carla\venv`（Python 3.12）里 `carla 0.10.0` | `pip list` |

**结论**：本机**能跑 CARLA**，但**只能跑 0.10.0**，而仓库是按 0.9.13 写的 → 必须移植；
且 0.10.0 这个本地构建是"精简版"（2 张地图、11 个车辆），所以路线与车型都要改。

## 2. 训练环境（新建，未污染其他 conda 环境）

`audiobook` conda 环境里已有 `torch 2.8.0+cu128`（可用 CUDA），因此新建一个
**继承其 site-packages 的 venv**，只补 RL 侧缺的包：

```powershell
E:\anaconda3\envs\audiobook\python.exe -m venv --system-site-packages venv
.\venv\Scripts\python.exe -m pip install "stable-baselines3>=2.4" "gymnasium>=1.0" "opencv-python>=4.10" pygame
.\venv\Scripts\python.exe -m pip install --no-deps <CARLA 0.10.0 cp311 wheel>
```

* venv 放在**仓库内**（`venv/`），而仓库 `.gitignore` 已经忽略 `venv` → 不会进版本库。
* `opencv-python` 必须**升级到 ≥4.10**：继承来的 4.9 是 numpy-1.x 构建，在 numpy 2.2 下
  `import cv2` 直接报 `numpy.core.multiarray failed to import`。
* 结果：`stable-baselines3 2.9.0` / `gymnasium 1.3.0` / `carla 0.10.0` / `torch 2.8.0+cu128`。

## 3. 代码移植（逐文件）

| 文件 | 改动 | 原因 |
| --- | --- | --- |
| `carla_env/wrappers.py` | `Vehicle` 默认车型 `vehicle.tesla.model3` → **`vehicle.lincoln.mkz`**；`color` 属性加 `has_attribute` 保护 | 本机 0.10 构建没有 tesla blueprint |
| `carla_env/wrappers.py` | `World.__init__` 的 `load_world('Town02')` → **参数化 `town`（默认 `Town10HD_Opt`）** | 本机没有 Town02 |
| `carla_env/envs/carla_route_env.py` | `import gym` → **`gymnasium`**；`metadata["render.modes"]` → `render_modes` | SB3 ≥ 2.4 走 gymnasium API |
| 同上 | `reset(*, seed, options) -> (obs, info)`；`step -> (obs, reward, terminated, truncated, info)`；内部步进拆成 `_step_impl` | gymnasium 五元组约定 |
| 同上 | Town02 专用的硬编码 `intersection_routes` 删除，路线改为**按当前地图随机采样 spawn 点对**（用 `self.route_rng` 可复现）；eval 路线索引越界时回退 | 本机 spawn 点只有 155 个且布局不同 |
| 同上 | 新增 `town` / `carla_exe` / `route_rng_seed` 参数；Windows 下可拉起 `CarlaUnreal.exe`（`-RenderOffScreen -nosound`） | 上游只会启 Linux `CarlaUE4.sh` |
| 同上 | 新增 `collision_flag`（`_on_collision` 里置位），`reset` 清零 | 区分"真碰撞"和"压线 / 超速 / 停车"这些终止 |
| 同上 | **`new_route()` 去掉 `set_simulate_physics(False/True)` 开关**，改为清零线速度/角速度 + `set_transform` 传送 | **本机 0.10.0 上这套开关会让自车永久失去物理**：软重置后 90 % 油门连续 40 步最高只有 0.5 km/h。SB3 在 `learn()` 开头会先 `reset()`，所以**每轮训练的整段都是冻住的车在跑**——第一版"策略学会停车不动"的结论就是被这个 bug 误导的。修后同条件 36.1 km/h（可用 `tools_safety/probe_reset_physics.py` 复现） |
| `carla_env/navigation/local_planner.py` | `RoadOption` 补上 **`CHANGELANELEFT = 5` / `CHANGELANERIGHT = 6`** | 原枚举缺这两项，`global_route_planner._lane_change_link()` 直接 `AttributeError: CHANGELANELEFT`，路线规划建不起来 |
| `carla_env/state_commons.py` | `import gym` → gymnasium；`torchvision` 改为**可选导入**；`maneuver` 观测**夹到 [0,3]** | ① 无 VAE 路径时不必装 torchvision；② 新增的 CHANGELANE*(5/6) 与 VOID(-1) 超出 `Discrete(4)`，会让 SB3 的 `nn.Embedding` 下标越界 → **CUDA device-side assert** |
| `utils.py` / `vae/utils/misc.py` | `import gym` → gymnasium；torchvision 可选 | 同上 |
| `config.py` | 新增 `SAFETY` / `SAFETY_PPO` / `SAFETY_UNSHIELDED` / `SAFETY_PPO_UNSHIELDED` 四个配置（`vae_model=None`、`map=Town10HD_Opt`、`safety` 块） | 无 VAE、可无头训练；安全参数集中可调 |
| 新增 `carla_env/safety/` | **CBF 安全层**（见 02 文档） | homework 的主体 |
| 新增 `train_safety.py` | 带 shield 的训练入口 | 上游 `train.py` 没有安全层、且依赖 VAE |
| 新增 `tools_safety/` | 冒烟 / 单测 / 对比 / 评估脚本 | 可复现的证据 |

## 5. 已知限制（要如实说）

1. **地图只剩 Town10HD_Opt**：原仓库的 Town01/02 路线、预训练 VAE、`tensorboard/` 里的历史
   模型都无法直接复用（它们是在 Town02 + VAE 观测上训的）。
2. **没有障碍物/交通参与者**：本轮的 CBF 是**车道/速度/曲率**三类（全部来自自车状态）；
   与前车的 TTC/间距约束留作下一步（需要先放 traffic 或加测距传感器）。
3. **0.10.0 首次启动会冻结一次**：出现过 `get_map()` 报
   `UnicodeDecodeError … byte 0xbe`（服务器卡在加载态）；**杀掉进程重新启动后即恢复**，
   这是本次遇到的一个操作性坑，已记在本文。
4. 训练仍受单卡算力限制：本地实测 **≈31 steps/s**（无渲染、同步模式）。
