# 05 · 参考控制器的隐藏 bug：转向符号反了 + 缺横向位置项

> 起因：用户看视频后提出"**不加安全逻辑的车也很奇怪，一直在向右打方向，是不是坐标系有隐藏 bug**"。
> 结论：**确实是 bug，而且在"参考控制器"里**（不是 CBF、也不是仿真器设置）。有两个独立原因。

## 1. 先把符号测清楚（`tools_safety/probe_steer_sign.py`）

CARLA 是**左手系**（x 前、y 右、z 上），转向符号很容易搞反，所以不靠猜、直接测：

| 施加的转向 | 车头 yaw 变化 | 横向位移 | `vehicle.get_angle()` |
| --- | --- | --- | --- |
| `steer = +0.6` | **+10.8°**（向右转） | **+0.43 m**（偏右） | **+0.360 rad** |
| `steer = −0.6` | −53.4°（向左转） | −4.30 m（偏左） | −1.110 rad |

**两条约定确认**：
* `steer > 0` = **向右**；
* `get_angle()`（= `angle_diff(lane_forward, vehicle_velocity)`）**指向右侧时为正**。

## 2. Bug ①：转向是**正反馈**

旧参考控制器写的是

```python
steer = +1.4 * ang        # ang = env.vehicle.get_angle(current_waypoint)
```

而 `ang > 0` 表示"车头偏向右侧"——此时**应该向左打**，它却**继续向右打**：
**越偏右 → 越往右打 → 更偏右**，典型正反馈。
实测（`probe_lane_tracking.py`，旧符号）：123 步就偏出 **7.8 m** 并触发 off-track 终止。

**修法**：`steer = −k·ang`（负反馈）。

## 3. Bug ②：只有航向项，**没有横向位置项**

只修符号还不够。诊断轨迹（修正符号后）显示：

```
t= 2.0s  e_y = +3.50 m   ang ≈ 0.0°   steer ≈ 0.00    ← 平行于车道，但整条车偏在外面
t=13.0s  e_y = +11.19 m  ang = +16°   steer = −0.35   ← 一直没被拉回来
```

即：`get_angle()` 只反映**航向**，不反映**位置**。车一旦与车道平行，航向误差为 0，
控制器就"满意"了——**它可以永远保持在偏出去 3.5 m 的平行线上**。

**修法**：改用 **Stanley 式**控制器，同时反馈航向与横向偏差

$$\delta = -\Big(k_\psi\,\psi_e + \arctan\frac{k_y\, e_y}{v}\Big)$$

（`e_y` 为相对当前车道中心的有符号横向偏差，代码见 `tools_safety/driving_control.py`）。

**修好后实测**（330 步，目标 18 km/h）：`|e_y|` 均值 **1.02 m**、多数时间 0.1–1.5 m，
跑满全程不再发散；而修之前是"偏 3.5 m 保持平行 → 继续发散 → 触发 off-track"。

## 4. 这个 bug 影响了哪些结论（重要）

| 结论 | 是否受影响 | 说明 |
| --- | --- | --- |
| CBF 单测 7/7 | ❌ 不受影响 | 纯数学，不经过控制器 |
| 仿真器设置审计 13/13 | ❌ 不受影响 | 只查设置与确定性 |
| 训练期安全指标（12k 步 ×2） | ❌ 不受影响 | RL 策略自己学转向，没用我这条控制器 |
| **"同一激进策略 开/关 shield"对照** | ⚠️ 部分 | 用的是**固定开环动作**（恒定 +0.55 转向），本意就是"开环烂策略"，作为"滤波器兜底"演示仍成立；但它描述的是"开环漂移"，不代表正常驾驶 |
| **演示视频（A/B/C、v1/v2/v3、开/关对照）** | ✅ **受影响** | 这些用了坏控制器：车一直在向右偏，**放大了滤波器的功劳**（滤波器其实是在救一个主动往路外开的司机） |
| **交互场景评测台的那张表** | ✅ **受影响** | 同上：不开 shield"每个场景都撞"很大程度上是**司机自己撞的**，不全是障碍物造成的 |

→ 受影响的两组结论**必须用修好的控制器重跑**才算数；我也已经把代码统一改成
`driving_control.lane_follow_action()`（负反馈 + Stanley），三处脚本都改用它。

## 5. 教训

* **手写控制器也要先做"符号判定实验"**：左手系 + `get_angle` 的自定义符号，靠推理很容易反；
  两条测量（`probe_steer_sign.py`）比读十遍代码都快。
* **只反馈航向的循线控制器是假循线**：它会稳定地跑在一条与车道平行的偏移线上。
  判断"能不能循线"要看 **`distance_from_center` / 有符号 `e_y`**，不能只看航向误差。
* **对照实验里的"基线"必须自己先站得住**：基线司机要是坏的，整个安全性收益都会被夸大。

## 6. 修好之后的复验（2026-10-04 晚）

用户反馈"重新跑之后还是感觉在往右打"——所以又做了一次**定量复验**，把"感觉"变成数字。

### 6.1 长跑统计（修正控制器，600 步 = 40 s，`seed=33`）

| 指标 | 数值 |
| --- | --- |
| 平均转向 | **−0.062**（略偏左，不是一直右打） |
| 右打（steer > 0.1）占比 | 16.7 % |
| 左打（steer < −0.1）占比 | **28.5 %** |
| 基本回正（\|steer\| ≤ 0.1）占比 | **54.8 %** |
| 平均 \|e_y\| | **0.62 m** |
| \|e_y\| < 1.0 m 的时间占比 | **79.7 %** |
| 触发 off-track 终止 | **无**（跑满 600 步） |

对照**修之前**：123 步就偏出 7.8 m 并被终止——所以"一直向右打"是**修之前**的症状，
修好后的转向是"多数回正 + 左右都有的修正"。

### 6.2 那为什么还会"看起来在右打"？两个原因

1. **手里的视频是旧的**：`demo_best_C_ref_seed33.mp4` / `demo_comparison_no_shield_vs_shield.mp4`
   是**修 bug 之前**录的，我一直没重录（只重跑了 benchmark）。这两段已移入
   `_INVALID_prefix_videos/`，并**用修正控制器重录**成
   `demo_best_FIXED_seed33_shield.mp4` 与 `demo_comparison_FIXED_no_shield_vs_shield.mp4`。
   新视频里 HUD 的 `steer (RL)` 是 **−0.35 ~ −0.41（向左修正）**，画面也不再往右偏。
2. **还有一个脚本漏改**：`tools_safety/probe_scenario.py` 里残留着 `steer = +1.0*ang`
   （正反馈）——已改为调用 `driving_control.lane_follow_action()`。全仓库再检索一次，
   除 `probe_lane_tracking.py`（本来就故意对比两种符号）外**没有别处再用旧符号**。

> "31 m vs 1.8 m"的旧表**保守得多**，因为旧表的基线司机本身就在往右撞。

### 6.4 这次排查留下的最重要一条

**"看起来奇怪"必须先量化再解释**：`mean_steer / 左右打占比 / |e_y| 分布 / 是否 off-track`
这四项一测，"一直右打"这种描述立刻能判真伪；而**在修好基线之前，任何安全性收益都不能当结论**。
